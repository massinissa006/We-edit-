# Security Specification — Portail Monteurs Vidéo (Phone + Access Code, Audience Targeting, 5-Min WhatsApp Hold, 6-Stage Workflow & Monteur Availability)

## 1. Data Invariants
1. **Strict Admin Governance & Monteur Email PII Isolation**: Only verified administrator (`massinissa@bmsinformatique.com`, `email_verified == true`) can create/edit/delete `/tasks`, manage `/monteur_accounts` (which stores private monteur emails, phones, and access codes), `/monteur_credentials`, and `/monteur_credentials/{credId}/invites`, transition missions through `First draft delivered`, `Reediting`, `Delivered`, `Done`, or reopen missions manually.
2. **Phone + Access Code Isolation & Self-Service Availability**: Monteur credentials use a 256-bit SHA-256 document ID (`cred_<64hex>` of `normalizedPhone:accessCode`). `/monteur_credentials` forbids `list` queries by non-admins and does not store monteur email addresses, preventing phone, email, or credential enumeration. Plaintext access codes and monteur email addresses live strictly in Admin-only `/monteur_accounts`. An active monteur may update ONLY `disponible` (boolean) and `updatedAt` on their own `credId` document; `active`, `phone`, `nom`, and `createdAt` remain immutable to non-admins.
3. **Audience Isolation (`Visibilite` = `Tous` vs `Selection`)**:
   - Tasks with `Visibilite == 'Tous'` and `Statut == 'Ouverte'` have `Ouverte_Pour_Tous == true`, making them discoverable via `where('Ouverte_Pour_Tous', '==', true)`.
   - Tasks with `Visibilite == 'Selection'` have `Ouverte_Pour_Tous == false`, preventing non-selected monteurs from listing or reading them from `/tasks`. Private invite copies live strictly inside `/monteur_credentials/{credId}/invites/{taskId}` for selected monteurs only.
4. **Atomic Direct Claim, 5-Minute WhatsApp Hold, Chef Monteur Confirmation & Monteur Start-Editing Gate**:
   - Claiming an `Ouverte` task transitions `/tasks/{taskId}` to `Assigned` with `WhatsApp_Contacte == false`, `Chef_Monteur_Confirme == false`, and a server-bounded 5-minute window `Claim_Deadline_Ms` (`request.time.toMillis() + 240s..360s`) alongside `/monteur_credentials/{credId}/missions/{taskId}`.
   - Confirming WhatsApp contact sets `WhatsApp_Contacte == true` atomically across both `/tasks/{taskId}` and `/missions/{taskId}` without altering `Chef_Monteur_Confirme`.
   - Only the verified Admin (chef monteur) can set `Chef_Monteur_Confirme == true` from the Dashboard.
   - Starting editing ("Commencer le montage") allows the assigned active monteur ONLY when `existing().WhatsApp_Contacte == true && existing().Chef_Monteur_Confirme == true` to transition `Assigned -> In progress` atomically across `/tasks/{taskId}` and `/missions/{taskId}`, while strictly denying self-promotion to `First draft delivered`, `Reediting`, `Delivered`, or `Done`.
   - Automatic expiration/reopen (`Assigned` -> `Ouverte`) by a monteur is strictly gated by server clock `request.time.toMillis() >= existing().Claim_Deadline_Ms && existing().WhatsApp_Contacte == false` and atomically removes the `/missions/{taskId}` record.
5. **Immutable Audit Timestamps & Safe URLs**: `createdAt`/`updatedAt` must match `request.time`; `Lien_Fichiers` enforces `^https?://.*`.
